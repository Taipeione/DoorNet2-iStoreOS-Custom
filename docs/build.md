# Reproducible V0.1 cloud build

Every DoorNet2 firmware compilation must run on a GitHub-hosted Actions runner. The Mac is for source changes, repository administration, and inspecting Actions logs/artifacts only. `scripts/build-v0.1.sh` enforces the hosted-runner environment and refuses local compilation.

The [`DoorNet2 V0.1 Cloud Firmware Build`](../.github/workflows/doornet2-v0.1-cloud-build.yml) workflow runs on every push to `main` and can also be started with `workflow_dispatch`. It checks out and records the exact repository commit, fetches the pinned iStoreOS commit from [`config/source.env`](../config/source.env), applies the DoorNet2 RK3399 support, and performs static Precheck before full compilation. Build output and logs are attached to that workflow run as a 30-day Actions Artifact, including on failure where available. The workflow summary records the commit, source pin, target, version, and image SHA256.

The build is considered cloud-compiled only when the Actions full-build job and artifact verification both pass. The artifact verifier checks `rockchip/armv8/embedfire_doornet2`, DoorNet2 V0.1, Linux 6.6.144, ext4 and squashfs sysupgrade gzip images, generated checksums, and rejects R76S/RK3576 contents. A failed run must be diagnosed from its attached logs; fixes are committed and retried a bounded number of times. No local compilation is a fallback.

The pinned base is iStoreOS 24.10.8 commit `a405f0378aef729f0f250c94b18a34a09b7d8890`. The firmware retains DoorNet2-specific RK3399 DTS, U-Boot integration, partition/image definition, and boot flow; R76S RK3576 files are not used. Clean-install LAN is `192.168.100.1/24`. DoorNet2 version labels use `V0.1`, then increment (`V0.2`, `V0.3`); do not use R76S version labels.

The workflow builds the full image after resolving pinned feeds and packages. It verifies every checked-out feed HEAD against its exact 40-character pin, runs `defconfig` again after applying package exclusions, and asserts those exclusions remain resolved before compiling the RK3399 Linux target and `doornet2-rk3399` U-Boot variant. It then runs the built-rootfs policy integration check under QEMU/binfmt. PassWall and PassWall2 remain disabled by default. SmartDNS, AdGuard Home, ChinaDNS-NG, and WeChatDirect are included/configured as documented in the package and policy tests. Device service lifecycle, DNS runtime, OTA restore on hardware, and boot behavior are not proven by compilation.

Files currently present under the ignored local `work/build-output` directory were produced by a prior local Docker build. They are historical development artifacts only: they are not GitHub Actions artifacts, do not satisfy the permanent cloud-build rule, and do not qualify as release inputs. Only artifacts attached to a passing cloud workflow run are eligible for subsequent review. A cloud compile is not real-device acceptance and does not authorize eMMC writes, partition changes, flashing, or a formal release.
