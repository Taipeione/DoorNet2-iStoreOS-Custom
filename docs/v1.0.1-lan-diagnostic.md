# DoorNet2 V1.0.1 LAN-only 连接记录

目标地址：`192.168.100.1`（用户确认的当前 DoorNet2 LAN 地址）  
测试范围：只读路由、TCP/22 和 SSH 连接测试。  
密码：未索要、未记录、未尝试。

## 实际结果

Mac 当前网络路由无法证明设备在本地二层可达。到目标地址的路由仍经由
当前默认网关，TCP/22 没有建立，SSH 返回超时：

```text
route to: 192.168.100.1
destination: default
gateway: 192.168.50.1
interface: en1

tcp22_rc=1
ssh: connect to host 192.168.100.1 port 22: Operation timed out
```

本次没有执行远端 shell，因此以下项目仍然是 `NOT TESTED`：

- 设备型号、内核和 OpenWrt 版本；
- `/proc/cmdline`、挂载表和分区表；
- eMMC/TF MMC 映射；
- TF 是否被 Linux 识别；
- rootfs 来源和混合启动；
- `fw_printenv`。

## 待设备可达时的只读命令

```sh
TARGET_IP=192.168.100.1
ssh -o ConnectTimeout=5 -o NumberOfPasswordPrompts=1 \
  root@"$TARGET_IP" '/usr/sbin/doornet2-boot-report'
```

如该工具不存在，使用项目 [LAN-only 采集方案](lan-only-acceptance.md) 中的
完整只读脚本。不得执行 `sysupgrade`、`fw_setenv`、`mtd`、`dd` 或 `reboot`。

## 证据边界

`192.168.100.1` 当前不可达只说明本次 Mac 到该地址没有建立 SSH 连接，不能
证明 TF 启动失败阶段，也不能证明设备没有启动。继续定位需要同一 LAN/VLAN
下的路由器 DHCP 记录、LuCI 可达性或真实串口日志。
